- 2026-11-05 · Schema, spec fields: shape-only checks on `name` (required), `version`, `description`, `omitted`, `colors` (required), `typography`, `rounded`, `spacing`, `components`; value syntax is left to design.md so nothing is reported twice; other top-level keys pass through. (S1)
- 2026-11-05 · Schema, `x-squadra`: strict (unknown keys are errors with a did-you-mean). Required: `version: 1`, all 8 `settings`, all 3 `effects` (YAML booleans + `blur: none|overlays|anywhere`), `fonts` (non-empty, unique). Optional: `style` (a preset name or a `./`/`../` file; a label only), `icons {library, brands?}`, `css` (relative path), `vendored`, `modes.dark.colors`, `zones`, `rules`. The plan's "mono + accent" step is stored as `mono`. (S1)
- 2026-11-05 · Dark mode: every `modes.dark.colors` key must exist in the light `colors` (error). Dark keys need not cover every light key: brand colors are the same in both modes. Dark values get a CSS-color check (hex, the named-color list, channel functions with 3 components + optional alpha, loose color()/color-mix()), since design.md never sees them. (S1; tightened after the GPT-6.1 Sol review, which also fixed: YAML alias errors and alias bombs returned as findings instead of throwing, own-property dark-key lookup, OS-independent relative `css` paths, globs over rule families, locating design.md paths on dotted keys)
- 2026-11-05 · Zones may change only the rule-switching settings (fill, edges, shadow, type, motion), effects and severities; a guidance setting in a zone is an error. `rules` keys must look like `group/rule` (globs allowed); a key matching no plan rule ID is a warning, not an error. (S1)
